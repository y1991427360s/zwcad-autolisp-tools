# ZW-auto_lisp 小命令目录规则（必须遵守）

本目录是 `ZW-auto_lisp` 项目下的临时/独立 AutoLISP 小命令工作区，主要面向中望 CAD 2026（ZWCAD 2026），兼顾 AutoCAD 2018。这里的规则用于约束 `E:\366256\ZW-auto_lisp\小命令` 目录内的日常开发。

本目录内的 `AGENTS.md` 与 `CLAUDE.md` 必须保持完全一致。更新其中任意一份后，必须立即把同样内容写入另一份。根目录的 `E:\366256\ZW-auto_lisp\AGENTS.md` 与 `E:\366256\ZW-auto_lisp\CLAUDE.md` 是项目总规则；本目录文件是“小命令”目录专用规则，不要求与根目录规则文件内容一致。

## 一、目录定位

1. 本目录用于编写新的、临时使用的、试验性的或一次性处理图纸的小命令。
2. 小命令默认作为独立 `.lsp` 文件保存，不直接进入整合版本。
3. 除非用户明确提出“整合”“加入整合版本”“放进 AA 整合”“同步到主模块”等要求，否则不得修改以下文件来集成小命令：
   - `E:\366256\ZW-auto_lisp\AA整合版本.lsp`
   - `E:\366256\ZW-auto_lisp\aa-loader.lsp`
   - `E:\366256\ZW-auto_lisp\命令索引.md`
4. 小命令可以依赖 CAD 内置 AutoLISP / Visual LISP 能力；如果依赖项目主文件中的公共函数，必须在文件注释中写明依赖来源和加载前提。

## 二、文件命名与放置

1. 命令写完后，一般以“命令名.lsp”作为文件名，直接放在当前目录，例如 `ABC.lsp`。
2. 文件名应尽量与主要 `(defun c:命令名 ...)` 入口一致，便于查找、加载和删除。
3. 一个文件优先只放一个主要命令；如果放多个命令，文件开头必须用注释列出所有命令入口和用途。
4. 临时辅助函数应加清晰前缀，避免污染全局命名空间或与整合版本已有函数冲突。

## 三、文件编码（最重要）

1. 所有 AutoLISP 文件（`.lsp`）必须保存为 ANSI / GBK 编码，绝对不允许 UTF-8、UTF-8 BOM、UTF-16。
2. CAD 相关文本文件（`.dcl`、`.scr`、`.mnl`、`.lin`、`.pat`）同样优先 ANSI / GBK。
3. 换行符必须是 Windows CRLF（`\r\n`），不允许 LF-only。
4. 中文字符串必须在中望 CAD 2026 与 AutoCAD 2018 中正常显示。出现任何 `\xef\xbf\xbd`、`?`、方块都视为严重 bug。

## 四、编辑 GBK 文件的正确方式（强制）

Codex、Claude Code 等工具的常规文本补丁可能按 UTF-8 处理文件。直接用普通文本补丁编辑 GBK 文件，可能把中文破坏成替换字符，造成不可逆损坏。

因此：

- 禁止对 `.lsp` / `.dcl` / `.scr` / `.mnl` / `.lin` / `.pat` 等 GBK 文件直接使用普通 UTF-8 文本补丁。
- 必须用字节级方式读写，且显式指定 `gbk` 编码。
- 写入后必须立即验证文件仍然是 GBK 且换行为 CRLF。
- 如果改动内容本身不含中文，可以通过脚本做 ASCII 字符串替换；如果补丁内容含中文，必须以 GBK 字节或 GBK 临时文件方式处理，不能把中文直接写进普通 UTF-8 补丁。

推荐 Python 方式：

```python
from pathlib import Path

path = Path(r"E:\366256\ZW-auto_lisp\小命令\命令名.lsp")

# 读
text = path.read_bytes().decode("gbk")

# 修改 text 后写回，确保 CRLF + GBK
out = text.replace("\r\n", "\n").replace("\r", "\n").replace("\n", "\r\n")
path.write_bytes(out.encode("gbk"))

# 验证
back = path.read_bytes()
assert b"\xef\xbf\xbd" not in back
back.decode("gbk")
assert b"\r\n" in back
```

PowerShell 写 GBK 文件时必须显式指定 936 编码，例如：

```powershell
[System.IO.File]::WriteAllText($path, $text, [System.Text.Encoding]::GetEncoding(936))
```

不要用 PowerShell 默认写入 CAD 相关文件。

## 五、修改与备份

1. 新建小命令时，直接在本目录创建对应 `.lsp` 文件即可。
2. 修改已有 `.lsp` 小命令前，必须先做字节级备份，命名格式建议：
   - `<原名>.bak_YYYYMMDD`
   - `<原名>.bak-encoding-YYYYMMDD-HHMMSS`
3. 备份必须通过字节级复制完成，不能触发编码转换。
4. 发现文件编码异常时，必须先恢复到最近的干净备份，再重新用 GBK 字节级方式修改。

## 六、命令内容规范

1. 每个小命令文件开头建议包含简短注释：命令名、用途、适用场景、是否依赖外部函数。
2. 入口函数使用 `(defun c:命令名 ...)`，命令名应简短、稳定，避免与已有常用命令冲突。
3. 小命令应尽量自包含，方便单独加载、单独复制、单独删除。
4. 临时命令也要尽量避免破坏用户环境；修改系统变量时，应保存原值并在结束或报错时恢复。
5. 批量几何处理优先使用 `ssget` 的空间过滤能力，避免把全图对象取出后在 LISP 中大范围遍历。
6. 在 ZWCAD 2026 中不要对大列表使用 `vl-sort` + lambda 比较器；需要排序时优先考虑空间过滤、分桶或更简单的数据结构。
7. 批量处理大量实体时，不要在循环中逐对象调用原生命令或 `entupd`；优先批量调用原生命令，逐实体 `entmod` 后统一 `redraw`，并只对批处理遗漏对象做兼容性补处理。

## 七、测试要求

1. 小命令完成后，应至少检查括号配平、入口命令名、编码和 CRLF。
2. 能在 CAD 中验证时，优先用中望 CAD 2026 实测。
3. 涉及中文提示、图层名、块名、文字内容时，要特别检查中文是否乱码。
4. 不以 WSL2 测试结果作为最终依据，因为路径、编码、COM 行为都可能不一致。

## 八、整合规则（强制）

1. 默认不整合：在本目录新增或修改 `.lsp` 小命令，不代表要修改整合版本。
2. 只有用户明确要求整合时，才可以把小命令并入 `AA整合版本.lsp`、加载器或命令索引。
3. 一旦执行整合，必须遵守根目录项目规则，包括主文件备份、GBK/CRLF 验证，以及 `AA整合版本.lsp` 开头命令清单维护。
4. 整合后，本目录中的原始小命令文件是否保留、改名或归档，必须按用户要求处理；没有明确要求时保留原文件。
