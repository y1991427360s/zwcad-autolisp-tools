## 日常使用

1. 双击项目根目录 `develop-on-sen3.cmd`，进入 sen3 的 Codex。SSH 使用已配置的 `sen3-via-sen5`；tmux 会保留断线前的会话。
2. 告诉 Codex 要修改的命令。完成后让它检查差异、运行命令索引生成器，将相关文件提交并推送到 `origin` 的 `optimize/robustness-and-cleanup` 分支。
3. 双击 Windows 项目根目录 `update-from-sen3.cmd`。只有已经提交并推送的改动才会被下载；服务器未提交的文件不会同步。
4. 在 Windows 原生 ZWCAD 2026 中重新加载 `(load "E:/366256/ZW-auto_lisp/AA整合版本.lsp")`，用测试图检查行为、中文和一次 U 整体撤销。

服务器目录：`/home/ubuntu/projects/zwcad-autolisp-tools`。
Windows 目录：`E:\366256\ZW-auto_lisp`，现有 CAD 加载路径不变。
连接命令：`ssh sen3-via-sen5`。VS Code 可使用 Remote - SSH 连接同一主机并打开服务器目录。

## 同步保护

更新脚本拒绝未提交修改和分支分叉，不执行强制覆盖。更新前将旧版和候选版保存到 `backups/remote-update-时间戳/`，检查 CAD 文件 UTF-8 无 BOM、替换字符，并在更新后核对 CRLF。备份是源码快照；需回退时先保留当前改动，再由 Git 生成回退提交，避免直接覆盖正在编辑的目录。

GitHub 是传输与版本管理中间站。Windows 不需要开放 SSH 服务，也没有新增公网端口。服务器沿用 ubuntu 用户已有 Codex 和 GitHub 认证，认证文件不进入项目。

## 开发边界

服务器负责编辑、静态检查及 Git；Windows 负责 CAD 实机验证。先读项目 AGENTS.md，修改整合文件前做字节级备份。源文件保持 UTF-8 无 BOM，CAD 文件保持 CRLF；Git 属性负责检出换行，但服务器编辑器保存时也必须保留 CRLF。

新增或修改命令后执行 `python3 gen_命令索引.py`，核对两份索引。Linux 静态检查不能证明 CAD 行为正确。服务器不得把未在 Windows 验证的功能描述为实机测试通过。

避免同时在 Windows 和服务器编辑同一轮源码。Windows 需要临时修改时，先提交并推送，服务器拉取后再继续开发。
